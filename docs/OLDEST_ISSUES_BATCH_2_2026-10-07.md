## #7 Apple cleanup source

The new provider-neutral repository callback runs after accepted confirmation and worker acquisition, before repository Storage/Memory/Auth deletion. Existing acceptance triggers withdraw Community visibility and disable recurring schedules before the callback; a provider failure leaves those effects applied to an accepted pending account.

Trusted Auth Admin identities provide Apple's subject, with no email/client-metadata or identity-row UUID substitution. Exchange identity verification fixes the JWKS origin, RS256 algorithm/key selection and exact issuer/audience/subject/time checks. Transport bounds headers/body duration and response bytes. Client secrets last300seconds per attempt. AES-256-GCM protects persisted refresh tokens with job/account/audience/subject associated data under a separate environment key.

Migration `20261007190000_account_provider_revocations.sql` adds a service-role-only RLS table/user index and fenced write RPC. Each write locks the accepted job before checking worker/expiry with wall-clock time. Immutable terminal markers permit repository restart after Auth removal; successful revocation clears ciphertext. A per-account insertion/acceptance fence preserves the accepted receipt, including retries after original challenge TTL. Initial acceptance rechecks expiry inside the database. Invalid confirmations make no Apple request. Provider failure produces a fixed503 and failed resumable job instead of success or raw token/error disclosure.

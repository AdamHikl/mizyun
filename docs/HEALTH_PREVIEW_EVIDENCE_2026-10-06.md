## Outcome and boundaries

- Strict weight/completed-workout schemas and pure source/window/duplicate rules, with no changes to manual body/workout/food records.
- Dev-only Account → Health connections → Weight & Workout Health Preview. Explicit category actions, source attribution, kg/lb, timestamps, requested range, and empty/partial/error/clear states.
- Foreground in-memory controller with deadlines, bounded pages, generation retirement and buffers cleared on departure/background/account unmount. No storage, network, analytics or Coach port exists in this feature.
- Owned Expo Swift/Kotlin module with per-type read-only permissions, guarded Android availability, opaque type/window paging tokens, native invalidation and no persistence. Existing steps runtime behavior remains unchanged; shared permission explanations now describe the added categories accurately.
- Production listing and direct route remain disabled. No server sync, calorie/trend/statistics changes, vendor cloud, outbound export, watches or developer access.

See [ADR-0045](adr/0045-ephemeral-health-previews.md). The rolling 30-day query is a product preview range, not a claim that Health Connect's first-grant historical boundary is a rolling limit. Actual readable coverage may be narrower. iOS cannot establish denial or zero from an empty read.

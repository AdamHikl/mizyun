# ADR-0053: Automatic decorative meal illustrations

Date:2026-10-09. Status: accepted for implementation; new live image generation remains default-off and acceptance-gated. Requirement NUT-10; issues#230/#233.

## Context

Adam requested Genmoji-like artwork for meals without photos, completely automatically, to preserve richer tracking with less time spent. A creation editor, confirmation step or image-dependent meal save would undermine that instruction. Apple’s current image-generation API uses a user-facing sheet and device availability checks, making it unsuitable for the universal automatic path.

## Decision

Use bundled AI-generated food illustration catalogs, selected locally from the meal name, as the immediate decorative fallback on iOS and Android for Pro and approved Launch Pro Pass accounts. Adam explicitly restricted meal visual display and retained photo saving to Pro on2026-10-09. A fresh server capability authorizes display with a bounded30-second memory lease, retired on blur/background/account changes; saved photos and private generation also enforce Pro at API/RPC/Storage boundaries. Unmatched dishes allocate no empty-plate placeholder. Retained real photos keep their existing private access, preview, retry and removal behavior and take priority when available. Artwork is not authoritative and never feeds nutrition calculations or saved ingredients.

For unmatched persisted dishes, separately ask an authenticated server endpoint to ensure a private illustration. The server derives the bounded dish name from the owned saved record. Never send nutrition, dates, notes, health profiles, images or identifiers to the image provider. Generated dishes are reused within the account; arbitrary health-related meal titles never enter a shared global catalog. The Gemini adapter remains behind a neutral port.

The response is ready/pending/unavailable. Pending generation is asynchronous and cannot block or fail food saves. Mobile observes it for a bounded foreground interval, retires requests on account/token/name changes and keeps matching catalog artwork on failures and hides unmatched artwork. Generated bytes use no native disk cache. Durable cache and separate image-attempt admission protect concurrency, repeat dishes and ambiguous provider outcomes. Cache records reference an owned source meal: source deletion, rename or photo change erases artwork. Separate owner usage counters retain charges after meal deletion and are included in account export and erased with the account. Anonymous environment totals survive account deletion. Account export and erasure retain authenticated owner-scoped access after Pro downgrade or consent revocation; revocation stops new generation and late publication. Failed/unknown requests remain charged and are not automatically resubmitted. Attempts are capped at5/user/day,30/user/month,50/environment/day,500/environment/month; one user and two environment jobs may run concurrently. A40-second whole-job deadline and120-second lease bound ambiguous work. Account export/deletion includes the private cache even while generation is switched off. New generation stays off until current consent, adult eligibility, provider switches, budgets and the existing synthetic-provider checklist permit it.

## Consequences

Common Pro meals get a food-specific visual without a per-meal provider request. A second synthetic16-food atlas adds toast, pudding, banana and other common categories. Background generation can improve uncommon dishes after acceptance, without adding user effort. Approximate icons may contain decorative ingredients absent from the real meal; presentation and accessibility identify illustrations separately from real photos. A bundled catalog can expand safely using synthetic concepts without user data. This adds no Apple Intelligence requirement or native dependency. Automated mocks do not establish generated artwork quality, real database isolation, provider cost/retention acceptance or native UX.

Previously issued signed photo URLs remain valid for their existing short lifetime (at most five minutes); downgrade prevents new feature URLs and reads. Stored media is preserved for owner export/erasure rather than deleted on downgrade. Free transient photo nutrition analysis is separate from retained meal visual display.

## Amendment — offline display of bundled icons (2026-10-23)

Adam reported that in airplane mode meal photos showed but the bundled meal icons did not. The capability check treated "server unreachable" exactly like a denial. Adam decided on 2026-10-23 to separate the two:

- When the capability check cannot reach the server (transport failure, a sign-in token refresh that cannot reach Auth, or the 10-second timeout), bundled catalog icons keep showing for up to 48 hours after the last server confirmation for that account on this device. The 48 hours matches the maximum age of other saved display data.
- The confirmation time is kept per account in SecureStore (`mizyun.meal-visuals.last-grant.<userId>`), so a cold offline launch works. It is removed with the account's local data.
- Any server answer still closes the lease immediately, including errors and the kill switch. An explicit denial (`mealVisuals: false`, 401, 402 or 403, or an expired session) also deletes the saved confirmation.
- Grace display is bundled icons only: no signed photo reads, no illustration generation, nothing on the edit screen, and it never counts as a Pro confirmation for saving or backing up photos. A device confirmation from the last 48 hours shows icons at once on a cold offline launch while the check runs; a server answer that arrives first wins.
- A captive portal or other non-JSON reply counts as a server answer (lease closes), not as unreachable.
- The 30-second lease, 20-second revalidation and account/token scoping are unchanged. Saved photos, signed URLs and private generation remain enforced by the server.

Accepted risk: an account that loses Pro while it cannot reach the server can keep seeing bundled icons for up to 48 hours. Implementation and verification: [offline icons handoff](../OFFLINE_MEAL_ICONS_2026-10-23.md).

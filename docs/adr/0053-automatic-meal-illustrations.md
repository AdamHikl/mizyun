# ADR-0053: Automatic decorative meal illustrations

Date:2026-10-09. Status: accepted for implementation; new live image generation remains default-off and acceptance-gated. Requirement NUT-10; issue#230.

## Context

Adam requested Genmoji-like artwork for meals without photos, completely automatically, to preserve richer tracking with less time spent. A creation editor, confirmation step or image-dependent meal save would undermine that instruction. Apple’s current image-generation API uses a user-facing sheet and device availability checks, making it unsuitable for the universal automatic path.

## Decision

Use one bundled AI-generated food illustration catalog, selected locally from the meal name, as the immediate decorative fallback on iOS and Android. Retained real photos keep their existing private access, preview, retry and removal behavior and take priority when available. Artwork is not authoritative and never feeds nutrition calculations or saved ingredients.

For unmatched persisted dishes, separately ask an authenticated server endpoint to ensure a private illustration. The server derives the bounded dish name from the owned saved record. Never send nutrition, dates, notes, health profiles, images or identifiers to the image provider. Generated dishes are reused within the account; arbitrary health-related meal titles never enter a shared global catalog. The Gemini adapter remains behind a neutral port.

The response is ready/pending/unavailable. Pending generation is asynchronous and cannot block or fail food saves. Mobile observes it for a bounded foreground interval, retires requests on account/token/name changes and keeps the catalog on all failures. Generated bytes use no native disk cache. Durable cache and separate image-attempt admission protect concurrency, repeat dishes and ambiguous provider outcomes. Cache records reference an owned source meal: source deletion, rename or photo change erases artwork. Separate owner usage counters retain charges after meal deletion and are included in account export and erased with the account. Anonymous environment totals survive account deletion. Account export retains access to existing records after consent revocation; revocation stops new generation and late publication. Failed/unknown requests remain charged and are not automatically resubmitted. Attempts are capped at5/user/day,30/user/month,50/environment/day,500/environment/month; one user and two environment jobs may run concurrently. A40-second whole-job deadline and120-second lease bound ambiguous work. Account export/deletion includes the private cache even while generation is switched off. New generation stays off until current consent, adult eligibility, provider switches, budgets and the existing synthetic-provider checklist permit it.

## Consequences

All meals get a useful visual without a provider request. Background generation can improve uncommon dishes after acceptance, without adding user effort. Approximate icons may contain decorative ingredients absent from the real meal; presentation and accessibility identify illustrations separately from real photos. A bundled catalog can expand safely using synthetic concepts without user data. This adds no Apple Intelligence requirement or native dependency. Automated mocks do not establish generated artwork quality, real database isolation, provider cost/retention acceptance or native UX.

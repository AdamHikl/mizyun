# ADR-0040 — Free exercise catalog and legacy identity

Date: 2026-10-04. Status: accepted for local implementation; exercise content and device release acceptance remain open. Work item: [#189](https://github.com/AdamHikl/mizyun/issues/189), EX-02/WO-06.

Adam approved replacing the confusing built-in exercise list using a free source and visible attribution. ExerciseDB.io remains a future upgrade. The existing catalog contains 888 definitions; the pinned RepDB Free snapshot contains 609. Neither count includes user-created exercises.

Use adapted [RepDB Free](https://github.com/RepDB/exercise-dataset) text inside Mizyun. Pin its 2026-10-04 schema-3 input with SHA256 `b651511287cd7e9261158598bf0263c56c19d2403ad8b57f68426c9c99d17421`. Its [data license](https://github.com/RepDB/exercise-dataset/blob/main/LICENSE-DATA.md) permits commercial app use with attribution but prohibits standalone dataset/API redistribution. The app repository was verified private. Preserve the visible linked credit `Exercise data by RepDB (repdb.co)` in Account → Legal → Credits. The existing authenticated catalog endpoint serves the app; do not turn it into a generic exercise-data distribution service.

The local browse/search catalog becomes 609 adapted entries. Familiar aliases, ranked normalized search, complete pagination, descriptions, numbered instructions, tips, common mistakes and precise equipment labels improve discovery and presentation. Coarse existing equipment enums remain for compatibility; unsupported specialized equipment conservatively requires full-gym access. Supplier safety tags do not become medical suitability policy. These changes do not certify professional correctness: every imported entry records `pending_professional` and a null professional review date. Per-entry qualified form/variant review remains required before release. Resolve questionable movement definitions and coverage gaps during that acceptance; swimming and outdoor cycling are absent from the replacement source.

Keep the original 888 definitions in an archive for saved-ID resolution. Reuse IDs only for deliberate equivalent-variant matches. Explicit lookup aliases do not rewrite persisted identifiers. Exact historical lookup continues to resolve archived definitions; fresh name/alias search selects active entries. Custom UUIDs, stored instructions, routines, workout sets, load progression and active-session snapshots are not migrated. Automatic prescriptions use only deliberate reused equivalent IDs in the original catalog order; newly imported specialty variants do not enter automatic selection. Exact canonical or unique known previous labels reuse saved user UUIDs for adding exercises and load progression; ambiguous matches and failed reads stop writes, and target updates retain existing metadata. Keeping the archive has a bundle-size cost that must be checked in the normal bundle gate.

Every active entry has a stable provider-independent ID, source identity/version/license and an explicit null demonstration. The future demonstration type binds assets to an exact variant and records format, provider, URI, license, attribution and review status. Animation playback, media import, visual form acceptance, reduced-motion behavior and native format verification remain separate work. Do not use paid preview media, or derive generative animations from RepDB illustrations: its free license prohibits that image use. Independently authored or separately licensed future media can attach without changing exercise IDs.

The deterministic importer rejects a changed snapshot hash and malformed records. Tests cover the 609 count, all 888 historical IDs, alias ranking, every page, API metadata and authentication, picker form presentation and attribution. Automated checks do not replace qualified exercise review, standalone Dev/device history/recovery acceptance or Production release evidence. See [research and coverage evidence](../EXERCISE_CATALOG_RESEARCH_2026-10-04.md).
